# Security policy

## Scope

edge-cv-lab is a lab for reproducing video-analytics failures on one machine. It is not a product, and nothing in it
is hardened for the internet: fixed passwords, no TLS, containers running as root, management APIs with default or no
logins (published on localhost only unless `LAB_BIND` is set). Run it on a machine and network you trust, and treat the
defaults below as things to replace, not to deploy.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository (Security tab, "Report a vulnerability"). If that is
not available, contact the author through the repository owner's GitHub profile, https://github.com/blmrk. Please do
not open a public issue for a vulnerability.

## Supported versions

Only `main`. There are no maintained releases.

## Dependency pinning

Pinned: `ultralytics==8.4.170` (`services/edge/requirements.txt:1`) and `torch==2.14.1`
(`services/edge/Dockerfile:7`) in the edge image, the pair the case studies' figures were measured on; the toxiproxy and
grafana images, by version tag, not digest (`docker-compose.yml:37`, `:85`). The edge image's default weights,
`yolov8n.pt`, are pinned by sha256 (`services/edge/Dockerfile:11-12`); no package or image pin carries a hash.

These pins are for reproducibility. Grafana runs `grafana/grafana-oss:11.2.10-security-01` (`docker-compose.yml:85`;
`/api/health` reports `11.2.10+security-01`), a later 11.2 release than 11.2.9+security-01, in which the advisory for
CVE-2025-4123 says the 11.2 line is fixed (https://grafana.com/security/security-advisories/cve-2025-4123/). That XSS,
rated CVSS 7.6, works without a login when anonymous access is on, as it is here (`docker-compose.yml:90`), and the
advisory notes that Grafana's default Content-Security-Policy blocks it; that policy stays on (`docker-compose.yml:93`).
On 2026-10-05, on a fresh lab (postgres, emqx, ingest and grafana) with the new image, `curl -sI` on `/` returns the
`Content-Security-Policy` header, an anonymous `/api/ds/query` runs `select current_user` as `grafana_ro`, the panel
queries on `zone_events` and `zone_occupancy` return no error, `/d/edge-cv-lab/edge-cv-lab` returns 200, and Grafana
logs the same error and warning lines at start as 11.2.0 does with the same mounts (missing `provisioning/plugins` and
`provisioning/alerting` directories, `xychart` registered twice), none from datasource or dashboard provisioning. The
exploit was not tried, before or after. What remains: the image is pinned by tag, not digest (the pull recorded
`grafana/grafana-oss@sha256:4ccffa04ef20f8b32aa8732a8c4dfc5a43b61004dba67dbe91063cd71284ff9f`, the digest to pin); it
was checked against this one advisory only, and no other pinned or floating version here was checked against published
advisories.

Not pinned: `torchvision` (`services/edge/Dockerfile:7`); the ranges in `services/edge/requirements.txt:2-6`,
`services/ingest/requirements.txt:1-2` and `services/sim/Dockerfile:3`; the harness extras in
`harness/pyproject.toml:9-12`, including `ultralytics>=8.3` in `[video]` (which the README's own-clip steps install) and
`[dev]` (which CI installs, `.github/workflows/ci.yml:11`); every transitive Python dependency (no lock file, no
`--require-hashes`); the apt packages `libgl1`, `libglib2.0-0` and `ffmpeg` (`services/edge/Dockerfile:2`); the base
`python:3.11-slim` (`services/*/Dockerfile:1`); the mediamtx and camera images at `:latest` (`docker-compose.yml:8`,
`:13`); emqx `5.8` and postgres `16-alpine`, which float within those lines (`:24`, `:45`); weights named by `MODEL`
other than the default (see Lab-only defaults), and any weights ultralytics fetches outside the edge image (the README's
own-clip steps through `harness[video]`, where `harness/scripts/dump_tracks.py:21` defaults to `yolov8n.pt`: no
checksum, no safe load). CI pins its actions to major tags, not commit SHAs
(`.github/workflows/ci.yml:8-9`); its token is read-only (`permissions: { contents: read }`, `:3`).
